# Documentation Development Standard

**Version:** `v1.0`
**Status:** `ACTIVE`
**Scope:** Technical and implementation documentation

## Purpose

Keep implementation documentation accurate, traceable, and maintainable.

## Rules

1. Documentation MUST describe approved and implemented behavior accurately.
2. Documentation MUST distinguish facts, decisions, assumptions, OPEN items, and UNKNOWN information.
3. API, architecture, data, security, and operational documentation MUST remain aligned with approved artifacts.
4. Documentation MUST NOT invent behavior to make the project appear complete.
5. Material implementation decisions SHOULD identify their source or approval where traceability is applicable.
6. Outdated documentation MUST be corrected when discovered.

## Boundary

This standard governs documentation quality. It does not create new requirements.
