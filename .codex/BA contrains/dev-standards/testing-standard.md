# Testing Development Standard

**Version:** `v1.0`
**Status:** `ACTIVE`
**Scope:** Software testing practices

## Purpose

Define consistent testing practices for approved implementation work.

## Rules

1. Tests MUST target approved behavior and implementation boundaries.
2. Test names and IDs SHOULD make the covered implementation item identifiable.
3. Tests MUST distinguish functional correctness from non-functional quality checks where applicable.
4. A missing test is not automatically a missing product requirement unless the applicable project policy defines it as such.
5. Tests MUST NOT invent unsupported behavior solely to increase coverage.
6. Failing tests MUST be reported with affected scope and evidence.
7. Test evidence MUST be current enough for the verification claim being made.

## Boundary

This standard governs how approved behavior is tested. It does not create additional product behavior or unsupported acceptance criteria.
